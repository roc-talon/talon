**Fix (G7, slice 260).** In `sql/tests/run.mjs`, the sqlite backend `run` and `batch` call `setReadBigInts(true)` on each statement before `run()`. The rowid is then a BigInt and never a JS number. No code reads the `run()` result, so no meaning changed; the expected rows did not change. Repro on Node 26.7.0 with this method: exact `4611686018427387905n`. `scripts/test.sh w1`: pass (14.4 s, budget 15); `run.mjs`: 59 passed, 0 failed. Node 26.13.x was NOT run here (no download). The pin of the Node version in the workflows is still open (D7).

**Fix (G8, slice 260).** In `sql/tests/run.mjs`, the creation, run and close of a backend for a case are inside one `try`. A backend error (for example a failed fetch) now prints `FAIL <backend> <case>` with a `backend error: ...` line and the exit code is 1. Checked with a throwaway copy that disposed Miniflare before the d1 case: `FAIL d1 schema/s3-names`, `backend error: Cannot use disposed instance`, `w1: 1 passed, 1 failed`, exit 1. The copy was removed. The time limit is not changed (it belongs to G5 and D4).
