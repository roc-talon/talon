# tln CLI usability review (before the first release)

Input: `research/cli-ux-review/COMMANDS.md` (the inventory), `DESIGN-CLI.md`, `DESIGN-RESOLUTION.md`, `cli/lib/Args.roc`, `cli/lib/Help.roc`, `cli/lib/Run.roc` and some command modules. Read on 2026-11-23. Design references are rule ids, because another session edits the design files. Code references are `file:line` from that read.

Point of view: a new user who knows cargo, npm, uv and go mod. The main question for each finding: "Does a plausible reading do something different from what the user expects, and is that result destructive, hard to undo, or silent?"

Severity:

| Severity | Meaning |
| --- | --- |
| High | An easy misread, with a destructive or silent wrong result |
| Medium | Inconsistent or confusing, but the user can recover |
| Low | Polish |

"Change type" column: **Design** = the design must change (needs a decision). **Code** = only the code changes, to match the design or to add text that the design leaves open (R-OUT2: output text is a proposal, not a design change).

Counts: High 4, Medium 13, Low 10 (27 findings).

## 2. Checked and consistent

These hold up. They are listed so that the coverage is visible.

| Area | Why it is fine |
| --- | --- |
| `install` / `add` / `i` | One command, every rule applies to each spelling (R-CM20). It matches `cargo add` and `npm install`. A name that is already a header alias with no selector prints "is in the header" and adds nothing (R-AD1). |
| `remove` / `rm`, `list` / `ls`, `update` / `up` | Same at top level, `tool`, `roc`, `cache` (R-CM19), except `roc channel` (UX15). |
| `remove` safety | The platform entry is refused (exit 2) and an entry that an app module imports needs `--force` (exit 11). `--dry-run` works. Header and `talon.toml` are in VCS. |
| Platform without `--platform` | `tln add basic-cli` stops and names `--platform` (R-AD33). |
| Short names | An ambiguous short name stops and lists full names (R-AD4). `x` and `tool install` never take a registry short name, because they run code at once (R-AD7). |
| `--frozen` | Same name and meaning as cargo (no index call, the header is the truth). Rejected (exit 2) on commands that write the header. |
| `--as` with 2 or more names | Exit 2 (R-AD28). |
| `init` | Never overwrites; removes what it made on a fail; `init package --platform` is an error. |
| `patch` | Refuses the platform and unmanaged entries; stops when the dir exists (R-PA1, R-PA8, R-PA14). |
| `publish`, `yank`, `move` | Run only in GitHub Actions with OIDC; `yank` and `move` only in `workflow_dispatch`. A local mistake cannot publish or yank. `yank --undo` and `move --undo` exist. |
| `cache clean` | Prompts with the size (R-NI7), has `--dry-run`, never removes compilers, tools or `compat.db`. `cache gc` takes a lock and keeps what known projects pin (R-GC5). |
| `roc link` | Removal never touches the link target (R-RR3, R-RM2). |
| Misplaced command flags | `--keep-going` without `--each`, `--from-source` on another tool, `--target` without `--smoke`, `--path` without `--git` all stop with exit 2 (only the message shape differs, UX20). |
| Safety switches | `--no-check` is refused for `roc use` and for an `upgrade` with a free nightly; `upgrade --strategy lowest` is refused; `update -i` in non-interactive mode is exit 2. |
| `--yes` | It never gives the share consent (R-NI16). Each prompt also has its own answer flag for scripts. |
| `--json` | One envelope; refused for `x` and `run <name>` with a stated reason (their output belongs to the child). |
| Flag position | Flags may stand before the command word (`tln --json list`); `--json` is found also when the parse fails, so a JSON caller always gets JSON. |
| `tool remove talon` | Has a prompt with 3 options in interactive mode and `--dry-run` (R-RM4); the risk is only the non-interactive default (UX10). |
